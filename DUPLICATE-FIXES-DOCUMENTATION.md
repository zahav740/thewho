# 🔧 Исправления проблем с дубликатами в системе управления заказами

## 📋 Описание проблем

Были выявлены и исправлены следующие критические проблемы:

### 1. 🚨 Обнуление операций при импорте дубликатов Excel
**Проблема**: При загрузке нового Excel файла, система находила дубликаты по номеру чертежа и при обновлении полностью удаляла все операции, включая выполненные, что приводило к потере прогресса работы.

**Причина**: В методе `updateExistingOrder` использовалось `await this.operationRepository.delete({ order: { id: existingOrder.id } })` которое удаляло ВСЕ операции без учета их статуса.

### 2. 🗑️ Полное удаление заказов из БД
**Проблема**: При удалении заказов из интерфейса они полностью удалялись из базы данных, что делало невозможной проверку на дубликаты в будущем.

**Требование**: Заказы должны удаляться только из интерфейса (soft delete), но сохраняться в БД для проверки дубликатов.

### 3. ❌ Отсутствие выбора действий с дубликатами
**Проблема**: При обнаружении дубликата не было возможности выбрать "заменить" или "оставить как есть".

## ✅ Реализованные исправления

### 1. 🛡️ Умное обновление операций (Smart Update)

#### Изменения в `ExcelImportWithDuplicatesService`

**Было:**
```typescript
// Удаляем старые операции и создаем новые
await this.operationRepository.delete({ order: { id: existingOrder.id } });
```

**Стало:**
```typescript
// КРИТИЧНО: НЕ удаляем выполненные операции!
// Удаляем только невыполненные операции
await this.operationRepository.delete({ 
  order: { id: existingOrder.id },
  status: 'PENDING'
});

// Добавляем новые операции только если их еще нет
for (const opData of orderData.operations) {
  const existingOp = await this.operationRepository.findOne({
    where: {
      order: { id: existingOrder.id },
      operationNumber: opData.operationNumber
    }
  });

  if (!existingOp) {
    // Создаем новую операцию только если ее нет
    // ...
  } else if (existingOp.status === 'PENDING') {
    // Обновляем только невыполненные операции
    // ...
  }
  // Выполненные операции НЕ трогаем!
}
```

#### Новые типы действий с дубликатами:
- ✅ **`replace`** - Умное обновление (сохраняет выполненные операции)
- ⚠️ **`replace_completely`** - Полная замена (сбрасывает ВСЁ - только по запросу)
- 🔄 **`merge`** - Умное объединение данных
- 🔄 **`restore`** - Восстановление удаленного заказа
- ⏭️ **`skip`** - Пропустить (оставить как есть)

### 2. 🗂️ Реализация Soft Delete

#### Изменения в сущности Order

**Добавлены поля:**
```typescript
@Column({ name: 'isDeleted', type: 'boolean', default: false })
isDeleted: boolean;

@Column({ name: 'deletedAt', type: 'timestamp', nullable: true })
deletedAt?: Date;

@Column({ name: 'deletedBy', type: 'varchar', length: 100, nullable: true })
deletedBy?: string;
```

#### Миграция базы данных
```sql
-- Добавляем поле isDeleted (по умолчанию false)
ALTER TABLE orders 
ADD COLUMN IF NOT EXISTS "isDeleted" boolean NOT NULL DEFAULT false;

-- Добавляем поле deletedAt (может быть NULL)
ALTER TABLE orders 
ADD COLUMN IF NOT EXISTS "deletedAt" timestamp NULL;

-- Добавляем поле deletedBy (может быть NULL)
ALTER TABLE orders 
ADD COLUMN IF NOT EXISTS "deletedBy" varchar(100) NULL;

-- Создаем индекс для быстрого поиска активных заказов
CREATE INDEX IF NOT EXISTS idx_orders_not_deleted 
ON orders ("isDeleted") 
WHERE "isDeleted" = false;
```

#### Изменения в OrdersService

**Новые методы:**
- `findByDrawingNumberIncludingDeleted()` - поиск включая удаленные (для проверки дубликатов)
- `restore(id: string)` - восстановление удаленного заказа
- `findDeleted()` - получение списка удаленных заказов

**Обновленные методы:**
- `findAll()` - теперь показывает только `isDeleted: false`
- `findOne()` - только активные заказы
- `remove()` - теперь выполняет soft delete вместо физического удаления

## 📱 Как использовать новый функционал

### Импорт Excel с проверкой дубликатов:

1. **Откройте страницу "База данных"**
2. **Нажмите кнопку "🔄 Excel (проверка дубликатов)"**
3. **Выберите режим:**
   - **🔍 Анализ** - для детальной проверки каждого дубликата
   - **⚡ Автоматический** - для массового импорта с заданными правилами

4. **При обнаружении дубликатов выберите действие:**
   - **✅ Умное обновление** - обновляет данные, сохраняет прогресс (рекомендуется)
   - **⚠️ Полная замена** - сбрасывает ВСЁ (только если уверены!)
   - **🔄 Объединение** - умное слияние данных
   - **🔄 Восстановление** - для удаленных заказов
   - **⏭️ Пропустить** - оставить как есть

### Работа с удаленными заказами:

1. **Удаление:** Заказы теперь помечаются как удаленные, но остаются в БД
2. **Просмотр удаленных:** `GET /api/orders/deleted/list`
3. **Восстановление:** `POST /api/orders/:id/restore`

## 🛡️ Безопасность данных

### ✅ Что защищено:
- **Выполненные операции** - никогда не удаляются при обновлении
- **Операции в процессе** - сохраняются при умном обновлении
- **История заказов** - мягкое удаление сохраняет все данные
- **Проверка дубликатов** - включает удаленные записи

### ⚠️ Предупреждения:
- **Полная замена** - сбрасывает весь прогресс (используйте осторожно!)
- **Физическое удаление** - теперь недоступно через интерфейс
- **Восстановление** - возможно только для мягко удаленных заказов
