# Система импорта Excel с проверкой дубликатов

## Описание

Модуль для импорта заказов из Excel файлов с интеллектуальной проверкой дубликатов и возможностью выбора действий пользователем.

## Возможности

### 🔍 Анализ дубликатов
- Автоматическое обнаружение дубликатов по номеру чертежа
- Сравнение различий между новыми и существующими заказами
- Детальный анализ изменений в количестве, дедлайнах, приоритетах и операциях

### ⚙️ Гибкие опции обработки
- **Заменить** - полная замена существующего заказа новыми данными
- **Объединить** - умное слияние данных с сохранением прогресса
- **Пропустить** - оставить существующий заказ без изменений

### 🚀 Режимы импорта
1. **Интерактивный режим** - анализ файла с возможностью выбора действий для каждого дубликата
2. **Автоматический режим** - быстрый импорт с предустановленным действием для всех дубликатов

## Архитектура

### Backend (NestJS)

#### Сервис: `ExcelImportWithDuplicatesService`

**Основные методы:**

```typescript
// Анализ файла на дубликаты
async analyzeExcelForDuplicates(file: File, colorFilters?: string[]): Promise<ImportResultWithDuplicates>

// Обработка с решениями пользователя
async processDuplicateResolutions(fileId: string, resolutions: BatchDuplicateResolution): Promise<ImportResultWithDuplicates>

// Автоматический импорт
async importOrdersWithAutoResolve(file: File, autoAction: 'replace' | 'skip'): Promise<ImportResultWithDuplicates>
```

#### Контроллер: `ExcelImportDuplicatesController`

**API Endpoints:**

- `POST /api/excel-import-duplicates/analyze` - Анализ файла на дубликаты
- `POST /api/excel-import-duplicates/process-with-resolutions` - Обработка с решениями
- `POST /api/excel-import-duplicates/import-auto` - Автоматический импорт

### Frontend (React + Ant Design)

#### Компонент: `ExcelImportWithDuplicates`

**Особенности:**
- Пошаговый мастер импорта (3 шага)
- Интерактивная таблица дубликатов с выбором действий
- Детальный просмотр различий между заказами
- Быстрые действия для применения одного решения ко всем дубликатам
- Статистика импорта в реальном времени

## Использование

### 1. Интерактивный импорт

```tsx
import { ExcelImportWithDuplicates } from '../components/ExcelImportManager';

function ImportPage() {
  return (
    <div>
      <ExcelImportWithDuplicates />
    </div>
  );
}
```

**Процесс:**
1. Загрузка файла
2. Система анализирует и находит дубликаты
3. Пользователь выбирает действие для каждого дубликата
4. Применение решений и завершение импорта

### 2. Автоматический импорт

```typescript
// Пропустить все дубликаты
const result = await duplicatesService.importWithAutoResolve(file, 'skip');

// Заменить все дубликаты
const result = await duplicatesService.importWithAutoResolve(file, 'replace');
```

### 3. Программное использование API

```typescript
// Анализ файла
const analysis = await duplicatesService.analyzeForDuplicates(file);

if (analysis.needsUserDecision) {
  // Подготовка решений
  const resolutions: BatchDuplicateResolution = {
    resolutions: [
      { orderDrawingNumber: "DWG-001", action: "replace" },
      { orderDrawingNumber: "DWG-002", action: "skip" },
      { orderDrawingNumber: "DWG-003", action: "merge" }
    ],
    defaultAction: "skip"
  };
  
  // Применение решений
  const result = await duplicatesService.processWithResolutions(
    analysis.fileId!,
    resolutions
  );
}
```

## Типы данных

### ImportResultWithDuplicates
```typescript
interface ImportResultWithDuplicates {
  created: number;                    // Количество созданных заказов
  updated: number;                    // Количество обновленных заказов
  duplicatesFound: DuplicateInfo[];   // Найденные дубликаты
  errors: Array<{                     // Ошибки импорта
    order: string;
    error: string;
  }>;
  needsUserDecision: boolean;         // Требуется ли решение пользователя
  fileId?: string;                    // ID файла для последующей обработки
}
```

### DuplicateInfo
```typescript
interface DuplicateInfo {
  orderData: ParsedOrder;             // Новые данные из файла
  existingOrder: ExistingOrder;       // Существующий заказ в БД
  differences: string[];              // Список различий
}
```

### DuplicateResolution
```typescript
interface DuplicateResolution {
  action: 'replace' | 'skip' | 'merge';
  orderDrawingNumber: string;
}
```

## Логика обработки дубликатов

### Действие "Заменить" (replace)
- Полностью заменяет существующий заказ новыми данными
- Удаляет все старые операции и создает новые
- Сбрасывает прогресс выполнения

### Действие "Объединить" (merge)
- Умное слияние данных:
  - Дедлайн: выбирается более поздний
  - Количество: увеличивается, если новое больше
  - Приоритет: повышается, если новый выше
  - Операции: добавляются новые, не удаляя существующие

### Действие "Пропустить" (skip)
- Оставляет существующий заказ без изменений
- Новые данные игнорируются

## Определение различий

Система автоматически определяет различия между заказами:

- **Количество**: `"Количество: 100 → 150"`
- **Дедлайн**: `"Дедлайн: 01.01.2025 → 15.01.2025"`
- **Приоритет**: `"Приоритет: MEDIUM → HIGH"`
- **Тип работы**: `"Тип работы: Фрезерная → Токарная"`
- **Операции**: `"Количество операций: 3 → 5"`

## Настройка и конфигурация

### Переменные окружения

```env
# Максимальный размер файла (в байтах)
MAX_FILE_SIZE=52428800  # 50MB

# Время жизни файла в кеше (в миллисекундах)
FILE_CACHE_TTL=3600000  # 1 час

# Лимит строк для обработки
MAX_ROWS_LIMIT=100000
```

### Структура Excel файла

Ожидаемая структура колонок:

| Колонка | Описание | Обязательно |
|---------|----------|--------------|
| A | Номер чертежа | ✅ |
| B | Количество | ✅ |
| C | Дедлайн | ✅ |
| D | Приоритет | ✅ |
| E | Тип работы | ❌ |
| F+ | Операции (группы по 4 колонки) | ❌ |

**Операции** (каждая группа из 4 колонок):
- Номер операции
- Тип операции (фрезерная/токарная)
- Количество осей
- Время выполнения

## Обработка ошибок

### Типичные ошибки и решения

| Ошибка | Причина | Решение |
|--------|---------|----------|
| "Файл не найден в кеше" | Истек срок жизни файла | Повторить анализ |
| "Неверный формат даты" | Некорректная дата в Excel | Проверить формат ячеек |
| "Номер чертежа не указан" | Пустая ячейка A | Заполнить обязательные поля |
| "Ошибка подключения к БД" | Проблемы с базой данных | Проверить соединение |

### Логирование

Все операции логируются с указанием:
- Имени файла и размера
- Количества найденных дубликатов
- Примененных действий
- Времени выполнения
- Ошибок и предупреждений

## Производительность

### Оптимизации

- **Потоковая обработка**: Файлы читаются построчно без загрузки в память
- **Кеширование**: Файлы кешируются между этапами анализа и обработки
- **Батчевые операции**: Множественные вставки/обновления в БД
- **Индексация**: Быстрый поиск дубликатов по номеру чертежа

### Ограничения

- Максимальный размер файла: 50MB
- Максимальное количество строк: 100,000
- Время жизни файла в кеше: 1 час
- Максимальное количество одновременных импортов: 10
